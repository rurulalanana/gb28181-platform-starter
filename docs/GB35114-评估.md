# GB/T 35114 国密改造评估

> 面向招标要求「必须支持 35114 国密认证」的技术评估。
> 结论：**这不是配置项能解决的需求，需要独立立项。** 本文说明差距、方案与验证条件。

## 1. 现状（已在平台上自检，见「系统设置 → HTTPS 与国密」）

实测环境：CentOS + nginx 1.14.1 + OpenJDK 21 + ZLMediaKit。

| 能力 | 状态 |
|---|---|
| JDK 国密算法（SM2/SM3/SM4） | ❌ 标准版 JDK 不含 SM 系列 |
| BouncyCastle | ❌ 未引入 |
| OpenSSL SM3 摘要 | ✅ 1.1.1k 支持 |
| OpenSSL SM2 曲线 | ❌ 1.1.1 未编入 SM2（`ecparam -list_curves` 无 sm2） |
| nginx 国密 TLS 套件（ECC-SM4-SM3） | ❌ 标准 nginx 不支持，需 Tongsuo/铜锁分支 |
| 设备证书 CA 体系 | ❌ 无 |
| 视频 35114 加解密 | ❌ ZLMediaKit 不做 |

这些是 35114 的**全部前提**，缺任何一项都无法端到端跑通。

## 2. 35114 到底要求什么

GB/T 35114—2017《公共安全视频监控联网信息安全技术要求》分 A/B/C 三级，
要求设备与平台之间做**双向证书认证**，并对视频数据做密码保护：

| 级别 | 信令 | 视频 |
|---|---|---|
| A 级 | 数字签名 | 数字签名 |
| B 级 | 数字签名 | 数据加密 |
| C 级 | 数字签名 | 加密 + 签名 |

技术要素：
1. **CA 体系**：为每台设备签发 SM2 证书，平台侧校验证书链。
2. **SM2**：非对称加解密与签名（替代 RSA/ECDSA）。
3. **SM3**：摘要（替代 SHA-256）。
4. **SM4**：对称加密（替代 AES）。
5. **密码模块**：多数项目要求国密局认证的硬件密码机/加密卡，软件实现不满足合规。
6. **视频加密**：在 RTP 载荷层加解密，需要媒体服务配合。

## 3. 关键差距（按工作量排序）

### 3.1 信令层：SM2 证书认证 + 信令签名

SIP 的 Digest 认证（当前实现）是**共享口令**认证，35114 要求的是**证书认证**：
设备携带 SM2 证书，平台验签 + 校验证书链 + 校验设备编码与证书绑定关系。

改造点：
- `gb28181-sip` 增加 `CertificateAuthProvider` SPI（与现有 `CredentialProvider` 平行）
- REGISTER 流程增加证书校验分支
- 需要引入 BouncyCastle（`bcprov-jdk18on` + `bcpkix-jdk18on`）
- 需要 CA 根证书与 CRL/OCSP 吊销检查

**工作量估计**：2~3 周（不含真机联调）。

### 3.2 传输层：国密 TLS

需要把 nginx 换成 **Tongsuo（铜锁，原 BabaSSL）** 或 Tengine+国密模块，
配置 `ssl_ciphers ECC-SM4-SM3`、`ssl_certificate` 用 SM2 证书。

风险：Tongsuo 是 nginx 的分支，替换后需重新验证录像 sendfile、
`auth_request`、WebSocket 升级等现有配置。**不能只改证书**。

**工作量估计**：3~5 天（含回归验证）。

### 3.3 视频层：SM4 加解密（最难）

35114 的 B/C 级要求视频内容加密。ZLMediaKit **不支持** 35114 的加密 RTP，
需要在媒体链路外挂加解密：

方案 A：改造 ZLM（C++）—— 侵入性大，且要跟上游版本持续同步。
方案 B：在平台侧做一层 RTP 代理，解密后再送入 ZLM —— 增加一跳，
影响延迟与性能，且要处理 SSRC/时间戳重写。
方案 C：换成支持 35114 的商业媒体服务器。

**这是整个项目里最重的一块，量级以「月」计。**

### 3.4 密码硬件

若招标明确要求「国密局认证密码模块」，则需要采购密码机/加密卡，
软件实现（BouncyCastle）在合规审查上通常不被接受。这属于采购项，不是开发项。

## 4. 建议的实施路径

不要一次做完整 35114。建议分三期，每期都能独立验收：

**一期（信令国密，2~3 周）**
- 引入 BouncyCastle + `CertificateAuthProvider`
- 平台能校验设备 SM2 证书、校验签名
- 可与国密厂商设备联调 A 级信令签名
- 交付物：可验证的证书认证链路 + 测试报告

**二期（传输国密，1 周）**
- 部署 Tongsuo nginx，启用 ECC-SM4-SM3
- 回归验证：录像播放、下载、签名鉴权、WebSocket
- 交付物：国密 HTTPS 站点 + 扫描报告（可用国密 SSL 检测工具验证套件）

**三期（视频国密，量级待评估）**
- 先确定加密方案（改造 ZLM / RTP 代理 / 换媒体服务）
- 需要设备侧配合，必须有真机才能推进

## 5. 现在必须先确认的信息

招标文件里通常写明了这些，请提供原文条款：

1. **要求哪个级别**：A（仅签名）/ B（加密）/ C（加密+签名）？
   只做 A 级的话，三期可以完全不做，工作量差一个数量级。
2. **是否指定 CA**：自有 CA / 指定第三方 CA / 由设备厂商提供？
3. **是否要求密码硬件**：有无「国密局认证密码模块」字样？
   有则需采购，且要确认平台侧接口形态（SDF / PKCS#11 / 厂商 SDK）。
4. **联调设备型号**：是否有支持 35114 的真机可供测试？
   **没有真机时，任何实现都无法验证** —— 这是最大的风险点。
5. **验收方式**：是功能演示、第三方检测报告，还是等保/密评？

## 6. 当前平台已就绪的部分

- 证书管理基础设施（上传、配对校验、nginx 配置生成、安全 reload）
- 运行时就绪度自检接口（`GET /api/v1/tls/gm-readiness`），可随时回答「还缺什么」
- `AccessControl` / `CredentialProvider` 两套 SPI 的既有模式，
  新增 `CertificateAuthProvider` 可沿用同样的插拔方式，不影响既有部署

也就是说：**一期开工不需要再改架构**，直接加 SPI 实现即可。

## 7. 一句话结论

> 35114 是密码体系工程，不是配置开关。若招标只要求 A 级信令签名，
> 一期二期合计约 4 周可交付；若要求 B/C 级视频加密，必须先把
> 媒体层方案和真机测试条件谈定，否则无法给出可信的工期。
